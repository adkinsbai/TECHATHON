# Tripo + Blender 路线

生成模型可以成为 3D 桌宠的外观资产。当前优先解决的是骨架与蒙皮；桌面透明窗口、鼠标行为、动作状态机和玩偶事件属于后续运行层。

## 分工

| 工具 | 当前职责 | 需要验收的部分 |
| --- | --- | --- |
| 图像服务 + Rodin | 统一角色风格，生成有辨识度的完整外观 | 四肢分离、默认姿态、轮廓、道具是否遮挡关节 |
| Tripo | 检查可绑骨性、预测骨架、生成蒙皮 | 头颈、肩髋、肘膝的位置及左右对应，短肢 / 大头比例适应性 |
| Blender | 保留生成骨架，检查和修权重，补专用骨与动作 | 关节变形、衣物与道具跟随、耳尾、穿模、导出往返 |
| 通用大语言模型 | 解释错误、生成检查脚本、整理评估和流程 | 不能把猜测的三维坐标当作可靠骨架，也不能用截图代替实际权重验收 |

已选择 Tripo + Blender。Tripo 官方 API 支持外部模型上传、rig-check 和多种 rig_type；Meshy 作为比较对象，其 API 明确主要适合结构清楚的标准双足人形。厂商文档支持不代表我们的每种玩偶都能绑好。

## 最小评估

先用同一份 Rodin GLB 比较，避免每次重生模型引入变量：

1. 普通双足卡通角色：验证主路径和骨骼命名。
2. 大头短肢兔子 / 站立水豚：验证团队真正需要的比例，以及耳朵和尾巴。
3. 四足动物：单独选择 quadruped，不能套双足模板。

每个结果记录输入模型、姿态、骨架类型、版本、耗时、服务商报告点数、可用骨骼、未绑定顶点、实际变形缺陷与人工修正时间。验证点包括抬臂、屈肘、转头、屈膝；道具模型再检查手持物和斜挎包。API 成功 / 骨骼数量 / 零未绑定顶点都不能代替视觉质量。

通过一个角色后再约定团队骨架版本与动作库。Mixamo 兼容命名只是一项命名约定，动作是否适配、根位移和关节旋转仍需重定向和验证。

## 当前集成约束

- 不用通用聊天模型直接猜全部关节与权重作为主方案。
- 不自动重新提交结果未知的付费请求。
- Tripo 预检查与绑骨是两个独立按钮；前者通过后仍须确认骨架类型。
- Tripo 返回没有动画的蒙皮 GLB 时如实显示，保留骨架再转 Blender。
- Blender 工程是新建的编辑文件，不包含生成模型原建模历史。
