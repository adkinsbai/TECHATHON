# 通信协议（电脑 ⇄ ESP32-S3）

所有数据都走 **WiFi + TCP**，和 USB 串口无关（串口只用于烧录和调试）。

```
┌──────────────┐    TCP 5000（板子主动连电脑）   ┌──────────────┐
│  电脑 (主机)  │ ◄─────────────────────────────► │ ESP32-S3      │
│ wifi_demo.py │   AUD / MODE / PING  →           │ board_main.py │
│              │   ← MIC / STAT / SENS / LOG      │              │
└──────────────┘                                  └──────────────┘
```

- **谁连谁**：板子是 TCP **客户端**，上电后连 `wifi.json` 里的 `host:port`；断线每 2 秒重连。
- **端口**：`5000`（可改，`wifi.json` 的 `port` 与主机端 `TCP_PORT` 要一致）。
- **编码**：小端（little-endian）。
- **没有 TLS、没有鉴权**：只在受信任的局域网里用（建议手机热点）。

---

## 1. 帧格式

每条消息是一帧：

```
偏移  长度  字段
0     4     MAGIC = AA 55 AA 55
4     1     type
5     2     len（payload 字节数，小端）
7     len   payload
7+len 2     checksum（小端）
```

`checksum = (sum(payload) + type * 31 + len) & 0xFFFF`

- `len` 最大 **4096**（超过按失步处理）。
- TCP 本身保证不丢不乱序，校验和用于兜底和发现实现错误。
- 收到不合法帧时应丢弃并重新寻找 `AA 55 AA 55`。

### 示例（AUD 帧，4096 字节 PCM）

```
AA 55 AA 55  01  00 10  ...4096 字节 PCM...  XX XX
└─ MAGIC ─┘  │   └ 0x1000 = 4096
             └ 0x01 = AUD
```

## 2. 电脑 → 板子

| type | 名称 | payload | 频率 | 说明 |
| --- | --- | --- | --- | --- |
| `0x01` | AUD | PCM 立体声 16bit LE，24 kHz | 约 23 帧/秒 | 每帧 4096 字节 = 1024 帧 = **42.7 ms** 音频（96 KB/s） |
| `0x02` | MODE | 1 字节：`0`空闲 / `1`播放 / `2`录音 | 状态变化时 | 录音和播放**不能同时**（半双工） |
| `0x03` | PING | 空 | 按需 | 板子回 PONG |

> AUD 的采样格式固定：**24000 Hz、2 声道、16 bit、小端、交错**（L,R,L,R…）。
> 电脑端负责解码（mp3/flac/wav/ogg）、软件音量和单声道转立体声。

---

## 3. 板子 → 电脑

| type | 名称 | payload | 频率 | 说明 |
| --- | --- | --- | --- | --- |
| `0x81` | MIC | PCM 单声道 16bit LE，24 kHz，≤2048 字节 | 录音时约 94 帧/秒 | 48 KB/s；板子已把 I2S 的 32bit 槽取高 16 位 |
| `0x82` | STAT | 8 字节（见下表） | 1 帧/秒 | 链路与缓冲状态 |
| `0x83` | PONG | 空 | 回应 PING | |
| `0x84` | LOG | UTF-8 文本 | 事件发生时 | 板子上的调试文字 |
| `0x86` | SENS | 4 或 8 字节（见下表） | **10 帧/秒** | 力传感器 |

### STAT（8 字节）

| 偏移 | 字段 | 含义 |
| --- | --- | --- |
| 0 | mode | 0 空闲 / 1 播放 / 2 录音 |
| 1 | fill | 板子环形缓冲占用百分比 0–100 |
| 2–3 | underruns | 欠载次数（>120 ms 没数据写进 I2S 记一次），uint16 LE |
| 4–5 | resyncs | 帧失步次数，uint16 LE |
| 6 | rssi | WiFi 信号强度 dBm，int8（-127 表示未连接） |
| 7 | drops | 环形缓冲满导致的丢帧数，饱和到 255 |

### SENS（4 或 8 字节，力传感器）

| 偏移 | 字段 | 含义 |
| --- | --- | --- |
| 0–1 | raw | 传感器 1 ADC 原始值 0–4095，uint16 LE |
| 2–3 | mv | 传感器 1 电压（毫伏），uint16 LE |
| 4–5 | raw2 | 传感器 2 ADC 原始值（仅 8 字节帧） |
| 6–7 | mv2 | 传感器 2 电压（仅 8 字节帧） |

采集参数：传感器 1 **ADC1_CH7 = GPIO8**，传感器 2 **ADC1_CH8 = GPIO9**，`atten = ATTN_11DB`（量程约 0–3.1 V）。
GPIO9 初始化失败时板子只发 4 字节老格式。电脑端只有在传感器 2 静置读数 ≥2500 且稳定时才认为它已接入，
GPIO9 悬空时读数乱跳，不会校准也不会触发。两个传感器在哪个部位，在设置里命名（`/api/body/settings` 的 `sites`）。
当前模块空载约 **4095（≈3.19 V）**，按压后下降；若 A/D 跳线在 D 侧则只有 0 / 4095 两档。

## 4. 音频参数与缓冲

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 下行码率 | 96 KB/s | 24 kHz × 2 ch × 16 bit |
| 上行码率 | 48 KB/s | 24 kHz × 1 ch × 16 bit |
| 板子环形缓冲 | **192 KB ≈ 2 s** | 抗 WiFi 抖动；比 1 s 更能吸收提前量的波动 |
| 电脑端提前量 | 1 s 起，按 STAT.fill 自适应（0.15–1.5 s） | 目标让板子缓冲稳定在 ~50%；**缓冲满要减小提前量，太空要加大** |
| 板子 I2S DMA | 32 KB ≈ 0.34 s | 再大（64 KB）会卡死 |
| 半双工 | 录音时不放音、放音时不录音 | 麦克风和喇叭共用一路 I2S |

**延迟参考**：从点击播放到出声约 0.3–0.5 s；语音识别（Vosk 小模型）约 2 s；TTS 合成约 0.5 s。

## 5. 主机端 HTTP API（网页控制台，默认 8081）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全部状态（歌单、播放、链路、麦克风、力传感器、日志） |
| POST | `/api/play?v=<索引>` 或 `?p=<文件路径>` | 播放指定歌曲（推荐用路径，索引会因歌单变化而漂移） |
| POST | `/api/toggle` | 播放/暂停 |
| POST | `/api/next` / `/api/prev` | 上一首 / 下一首（自动跳过不可播文件） |
| POST | `/api/volume?v=0..100` | 音量（软件衰减，默认 2%） |
| POST | `/api/record` | 开始 / 停止录音（录音→识别→回复） |
| POST | `/api/say?text=...` | 让音箱念一段文字 |
| POST | `/api/understand?f=<inbox 里的 wav>` | 对已有录音重新走一遍识别+回复 |
| POST | `/api/mode?v=agent\|local` | 回复方式：交给 Codex / 本地规则 |
| GET | `/mic/<文件>`、`/inbox/<文件>` | 下载录音 |
| GET | `/wiring` | 三合一接线图 |

## 6. 语音闭环的文件约定

录音结束后，控制台会把文件放到 `wifi/inbox/`：

```
inbox/rec_20261017-140512.wav       录音（24 kHz / 16bit / 单声道）
inbox/rec_20261017-140512.wav.json  元数据：时长、峰值、时间
inbox/pending.txt                   识别结果，等待回复
inbox/done_HHMMSS.txt               已回复的存档
```

回复写进 `wifi/reply.txt`，控制台会在 1 秒内用 TTS 合成并通过 AUD 帧推给板子播放，然后把 `pending.txt` 改名为 `done_*.txt`。

---

## 7. 扩展建议

- 新增消息类型时保持 `type` 分段：`0x0x` 主机→板子，`0x8x` 板子→主机。
- 单帧 payload 不要超过 4096；大数据请分包。
- 若将来改 UDP，现有的 checksum 和 MAGIC 可以直接复用，但需要自己处理丢包与乱序。

## 8. 排障：看 STAT 里的三个计数

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| `drops` 持续增长 | 板子环形缓冲被冲满，**音频被跳过**（听感是"顿一下"） | 减小电脑端提前量，或加大板子 `RING_SECONDS`；两者之和要留余量 |
| `underruns` 在播放中增长 | 板子**断粮**，I2S 没数据（听感是爆音/静音） | 查 WiFi：RSSI 低于 -40 或频繁 `10054` 断连时先修网络 |
| `resyncs` 增长 | 帧长度/校验失败，字节流错位 | 检查发送端是否整帧发送（非阻塞 socket 必须循环发完） |

启动后最初的 1–2 秒出现几次 `underruns` 是正常的（缓冲还没灌满）。
