# 把同一个小暖接到实体上

电脑上的 Companion 继续保存原来的人设、聊天和记忆；ESP32-S3 负责麦克风、喇叭和压力输入。实体桥接程序通过电脑本机的 Companion 接口对话，不创建第二个人设或数据库。

实体的语音识别使用电脑本地 SenseVoice，语音合成使用微软·晓伊（edge-tts，与网页同一个音色，需联网）。实体使用 `/api/body/asr` 和 `/api/body/tts`。识别模型缺失会明确报错；合成失败会重试，仍失败则这句不出声，不会换成别的声音。语言模型对话仍沿用原 Companion 的既有配置。

## 第一次准备电脑

使用 Python 3.12。先安装 `body-requirements.txt` 中的桥接依赖，并确保原 Companion 自己的依赖和本地识别模型已就绪。这里不复制、更换或下载原有的人设、模型和聊天数据。

在本仓库目录打开 PowerShell，使用你电脑上的实际路径：

```powershell
python -m pip install -r body-requirements.txt -r companion/requirements.txt
python install_companion.py --target '原来的 Companion 文件夹' --remember
```

安装器只处理 `app/server.py`、`app/body_runtime.py` 和 `static/` 下六个页面/脚本/样式文件。所有定位点先校验，成功后才写入；源码备份在目标 Companion 的 `.body-backups/本次编号/`，附带清单和安装后哈希。安装器不读取、复制或替换 `.env`、`data/`、人设和模型。不要把整个 Companion 文件夹复制进本仓库。

可以重复安装：页面钩子只保留一份，新的扩展源码会更新。若原源码版本不匹配，会在写入前停止；若写入途中失败，会恢复本次仍未被别人再次修改的文件。若同时有人编辑了源码，安装器保留对方的修改并报错。备份只覆盖本次变动的源码；回退时先停止已确认身份的服务，再按备份清单逐个恢复，新增的扩展文件按清单移除，勿整目录覆盖。

`--remember` 将 Companion 路径和这次使用的 Python 路径存入本仓库的 `.local-body.json`；该文件及日志、备份均已忽略，不应提交到 Git。换电脑后重新执行上面的安装命令即可。

## 每次启动

双击仓库根目录的 `start-body.cmd`。也可明确指定路径：

```powershell
.\start-body.ps1 -CompanionRoot '原来的 Companion 文件夹' -Python 'Python 3.12 的完整路径'
```

启动入口检查依赖和源码，复用已经运行且具有实体接口的 Companion；需要加载新后端时，仅在监听进程确认为 `uvicorn app.server:app` 后重启。无法识别的服务不会被结束。Companion 只监听 `127.0.0.1:8765`，浏览器继续打开原来的小暖网页。

实体桥接默认执行：

```powershell
python -m body_bridge --companion-url http://127.0.0.1:8765 --port 5000 --volume 10
```

TCP 5000 一次只能由一个程序占用。请先关闭旧 `wifi_demo.py`、`agent_demo.py` 或其他音频演示；启动器发现冲突会显示 PID 并停止启动，不会擅自结束它。已确认是同一地址和端口的桥接进程会被复用；其当前网页音量设置继续有效，重开启动入口不强制覆盖已保存的设置。

运行日志在 `.body-runtime/`，`services.json` 记录本次确认的 Companion 和桥接 PID，启动错误另存 `startup-error.log`。排查时先看最新 `*.err.log`。日志中的“等待板子连接”只表示电脑服务就绪，不代表硬件已经通过验收。

## 连接板子

1. 板子只支持 **2.4GHz Wi-Fi**，电脑和板子需要在同一个局域网。避免开启客户端隔离的访客网络。板子 `wifi.json` 的 `host` 填电脑在该网络上的 IPv4，`port` 填 `5000`，不要填 `127.0.0.1`。
2. Windows 防火墙需要允许该电脑在可信的专用网络接收 **TCP 5000**。无需把 Companion 的 8765 端口开放给局域网，也无需路由器端口映射。
3. USB 只用于首次识别芯片、配置 Wi-Fi 和部署已核对的固件；运行期间的音频和传感器数据走 Wi-Fi。现有 USB 线仍可供电。
4. 本次已从 **COM11** 读取并确认 MicroPython 1.25.0 / ESP32-S3 Octal-SPIRAM，并备份了板上相关文件；更新的 `board_main.py`、Wi-Fi 配置和启用标记均已通过 SHA256 读回核验。板子已接入 Wi-Fi 和电脑 TCP 5000。换板时仍须重新确认身份，不能只按 USB 名称选择刷写参数。
5. 启动/重新校准时让压力传感器保持**空载**，手不要压在上面。网页实体面板应显示新鲜的连接状态、压力读数和音量；页面提供校准及录音控制。

Wi-Fi 密码保留在忽略的本机配置和设备中，勿写入文档、日志或提交记录。换网络后重新设置电脑 IPv4 和 Wi-Fi 配置。已确认的同款板可使用 `tools/body_device.py --port COM11 --config firmware/wifi.json --backup runtime/device-backup-新的编号`：先备份和核对来源，再写入并校验；未知的板上源码会安全停止，保留备份。正常硬复位会执行 `main.py`，原始 REPL 中的软复位可能跳过启动程序。

## 怎么说话和触碰

按住右手压力传感器说话，松手后发送（左手只感知触碰，两只手 1 秒内一起按是抱抱）：超过最短录音时长的按压会将录音交给同一个小暖识别和回复；单次录音最多 **15 秒**。短于约 **0.35 秒**的触碰按一次物理事件处理，不向模型发送每秒十次的原始压力采样。压力只表示接触；除了两只手一起按这个约定手势，不用它判断拥抱、位置或情绪。

喇叭和麦克风是半双工：播放时不录音，再次按下可以中断播放。断线会丢弃未完成录音和待播语音，避免重连后重放旧内容。固件源码也在模式变化时清空播放环形缓冲；这项变化需要将核对后的新版 `board_main.py` 部署到实板才生效。

实体连接新鲜时，实体接管自动语音输出，两个网页继续同步文字和表情；网页音色预览仍可手动播放。默认音量 **10% 指 PCM 软件振幅乘以 0.10**，不等于经过声压标定的 10% 响度。不要因软件测试通过就直接提高音量；先在实际距离下从低音量试听。

## 验收记录应分开写

软件可通过隔离数据和模拟板子验证：按压防抖/迟滞、空载校准、录音上限、10% PCM 缩放、尾包补零和播放排空、发送失败有界、断线恢复、实体事件去重、过期连接状态、同库对话和双页面同步。测试命令：

```powershell
python -m unittest discover -s tests -v
```

本次实板已确认：芯片身份、源文件部署读回、Wi-Fi/TCP 连接、FSR 空载读数与校准、实体录音状态回传。当时的本地 SenseVoice/Kokoro 接口已用合成语音做识别环回（合成现已改为晓伊），未向聊天写入测试内容。真实麦克风可懂度、扬声器听感和末尾完整性、打断手感与长时间 Wi-Fi 稳定性，仍需真人按住说话、松手试听后验收。软件及部署记录见 `XIAONUAN-BODY-VERIFICATION.md`。
